# knowledge-dock 文档体系

knowledge-dock 是为 AI 智能体与研发团队构建的自维护工程知识中枢与智能体编排工作空间。系统基于 Git 作为唯一事实源，通过代码变更驱动增量核验，将人工排障经验收敛至待审池缓冲流转，在云端提供权威最新只读视界，实现工程知识的全自动维护与自生长闭环。

---

## 为什么需要 knowledge-dock

在基于大模型与多智能体协同的高频研发体系中，传统知识库普遍面临三大困境：

- 维护严重滞后：业务代码频繁发版，人工维护文档成本极高且难以持久；
- 知识极易失效：本地工作区代码滞后，检索到过期陈旧知识导致排障误判；
- 贡献缺乏受控：直接修改正式文档导致结构碎片化与未经求证的推测污染。

knowledge-dock 的核心定位并非替代搜索引擎或通用检索增强生成，而是从根本上解决工程事实的时效性与准确性问题：

> **RAG 解决找到答案，knowledge-dock 解决保证答案仍然正确。**

---

## 核心设计原则

- **Git 是唯一事实源**：代码与正式知识均由版本控制系统纳管，不构建脱离代码的外部信息孤岛；
- **代码变化不等于知识更新**：业务代码变更仅触发核验，只有业务语义与对外契约失效时才触发文档更新；
- **人工贡献统一进入待审池**：排障经验与人工补充必须经过结构化缓冲池，交叉核验后再转正入库；
- **智能体负责整理维护**：人类工程师提供关键事实与证据，智能体负责上下文对齐、格式规范与持续维护。

## 架构总览

```text
                 Git Repository
                       │
                       ▼
                 Change Detector
                       │
                       ▼
              Knowledge Maintenance Agent
                 │              │
                 ▼              ▼
       Knowledge Update   Knowledge Inbox
                 │
                 ▼
        Knowledge Service (HTTPS 443)
                 │
      ─────────────────────────────────
      │               │               │
    Agent            IDE          Debug Tool
```

系统在物理层与逻辑层实现了职责清晰的分离：

- **服务端事实平面**：运行于单容器内，基于 ActionDock 规范统一收敛在 HTTPS 443 单一端口。通过只读查询视图（`sk`）与特权维护视图（`skm`）实现细粒度权限隔离，提供代码检索、受控编辑、分支同步与待审池服务；
- **客户端控制平面**：纯本地轻量批处理调度器，负责多仓增量巡检、系统知识跨仓聚合与待审池串行消费，命令行严禁附加全局控制选项；
- **智能体技能资产**：明确划分贡献守门（`knowledge-contributor`）、维护转正（`project-knowledge-maintainer`）与总控编排（`knowledge-maintenance-orchestrator`）职责矩阵。

## 快速上手概览

- **连接代码仓库**：在服务端清单中配置需要纳管的业务代码仓与系统知识仓；
- **启动服务容器**：配置双鉴权令牌并启动一体化 Docker 容器，对外暴露标准 443 单端口多视图服务；
- **运行首次巡检**：通过客户端流水线调度器执行初始扫描，自动建立各仓库检查点基线水位；
- **调用知识接口**：本地开发工具或排障智能体通过只读视图检索全仓代码与最新架构文档。
